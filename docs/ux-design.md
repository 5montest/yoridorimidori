# UX 設計 — 一般ユーザー向け目的地設定と画面品質

- 版: v1.0（2026-10-30）
- ステータス: 実装方針（Lead 決定）
- 前提: [requirements.md](requirements.md) / [architecture.md](architecture.md) / [destination-ux-apis.md](docs/research/destination-ux-apis.md)（API 実現性）
- 目的: **座標の直打ちを廃止**し、一般ユーザーが説明なしで目的地を設定できる UI にする。開発者向けデバッグ画面は通常フローから排除する。

---

## 1. 設計原則（一般ユーザー向け）

| # | 原則 | 具体化 |
|---|---|---|
| UX-1 | **座標を見せない・打たせない** | 一般 UI に緯度経度の入力欄を置かない。座標は内部表現。開発メニュー（隠し）のみ |
| UX-2 | **1 タップで目的地へ** | メイン画面から「目的地を選ぶ」1 タップで選択画面へ。初回は選択画面を自動表示 |
| UX-3 | **選び方は 4 つ + α** | ①地図から選ぶ ②場所を検索 ③現在地 ④最近使った場所／お気に入り。＋共有リンク取り込み |
| UX-4 | **専門用語を出さない** | 「精度 8 m」「鮮度 3 秒」→「GPS：良好」「コンパス：やや不安定」。詳細は折りたたみシート |
| UX-5 | **失敗しても迷わせない** | 権限拒否・位置不明・オフライン時に「次に何をすればよいか」を 1 文で提示 |
| UX-6 | **デバッグ機能は隠す** | Mock・記録・座標入力は「開発メニュー」（タイトル長押し）に隔離。通常画面には出さない |
| UX-7 | **大きな文字・大きなタップ領域** | 主要数値は大きく、ボタンは最小 48dp、コントラスト比 4.5:1 以上 |
| UX-8 | **日本語として自然** | 「目的地は右後ろ」など話し言葉。英語の enum 名を出さない |

## 2. 画面一覧（刷新後）

| # | 画面 | 役割 | 変更 |
|---|---|---|---|

| S5 | 検索結果 | 場所名・住所の候補リスト | **新規** |

### 削除・置換するもの
- `DestinationAddScreen`（緯度・経度の TextInput）→ **一般フローから削除**。開発メニュー内の「座標で設定（開発用）」に移動
- メイン画面の `Mock: OFF` ボタン・「記録」タブ → 開発メニューへ移動
- ステータスパネルの常時表示（精度/鮮度/警告の 3 行）→ 1 行サマリ + タップで S6

## 3. 主要フロー

### F1 初回起動
```
起動 → S1 オンボーディング（3 枚・スキップ可）
  → 位置情報の許可ダイアログ（理由を表示）
  → S3 目的地を選ぶ（初回は自動表示）
  → 目的地決定 → S2 メイン（鳥が方向を指す）
```

### F2 地図から選ぶ（座標を打たない主経路）
```
S2「目的地を選ぶ」→ S3 → 「地図から選ぶ」→ S4
  → 地図をタップ（または中央ピンをドラッグ）→ ピン位置を逆ジオコーディング
  → 「この場所を目的地にする」→ S2
```

### F3 場所を検索
```
S3 検索バーに「東京タワー」「渋谷区役所」等 → S5 候補（名前・住所）
  → 候補タップ → 確認シート「ここを目的地にしますか？」→ S2
```

### F4 現在地・最近・お気に入り
```
S3 「現在地を目的地にする」→ S2
S3 「最近使った場所」/「お気に入り」の行タップ → S2
S2 目的地チップの ☆ でお気に入り登録
```

### F5 共有リンクから取り込む（Google マップ等）
```
Google マップ → 共有 → 「コピー」→ 本アプリを開く
  → S3 上部に「コピーしたリンクから目的地を設定」バナー
  → タップ → リンク解析 → 座標が取れたら確認シート → S2
  （短縮リンクはネット接続時のみ解決。失敗時は「リンクを読み取れませんでした」）
```

### F6 ディープリンク
```
外部から yoridorimidori://set?lat=35.65&lon=139.74&name=東京タワー
（開発中は exp://host:8081/--/set?...）→ 確認シート → S2
```

### F7 開発者
```
S2 のタイトルを 3 秒長押し（または 7 回タップ）→ S7 開発メニュー
  → Mock 操作 / 記録 / 座標で設定 / シナリオ
```

## 4. 画面仕様（ワイヤーフレーム）

### S2 メイン（ナビ）
```
┌────────────────────────────────────┐
│ [東京タワー ▾]                 ☆   │ ← 目的地チップ（タップで S3）
│                                    │
│              🐦（オオハシ）          │ ← クチバシが目的地の方向
│                                    │
│              1.24 km               │ ← 距離（最大の文字）
│        目的地は 右ななめ前           │ ← 方向の言葉（8 方位）
│                                    │
│  ┌──────────────────────────────┐  │
│  │ GPS：良好   コンパス：普通     │  │ ← 1 行サマリ（タップで S6）
│  └──────────────────────────────┘  │
│                                    │
│      [ 目的地を選ぶ ]               │ ← 主要ボタン
└────────────────────────────────────┘
```
- 到着時: 距離 0 m / 「到着しました」/ 鳥は上向き / ボタンは「目的地を変える」
- 位置未取得: 鳥はニュートラル / 「現在地を探しています…」/ 再試行ボタン
- 権限拒否: カードで理由 + 「許可する」「あとで」

### S6 状態の詳細（ボトムシート）
- GPS: 精度の目安（良好/普通/不良）＋ 更新からの経過（秒）
- コンパス: 精度・校正の状態・真北/磁北
- 警告一覧（一般向け文言）
- 記録（開発メニューに移動）

## 5. 文言（一般ユーザー向け）

| 内部状態 | 表示（要約） | 詳細（S6） |
|---|---|---|
| `fresh` | 最新 | 1 秒前に更新 |
| `aging` | やや古い | 3 秒前に更新 |
| `stale` | 古い | 12 秒前に更新。屋外で再取得してください |
| `lost` | 取得できていません | 位置情報が 30 秒以上更新されていません |
| GPS `good` | 良好 | 誤差 約 8 m |
| GPS `poor` | 不良 | 誤差 約 40 m。屋外でお試しください |
| 方位 `good` | 良好 | コンパスの精度: 高 |
| 方位 `uncalibrated` | 要調整 | 端末を 8 の字に振ってください |
| `magnetic-north` | （詳細のみ） | 磁北基準で表示しています |

方向の言葉（8 方位）: 真っすぐ前 / 右ななめ前 / 右 / 右ななめ後ろ / 真後ろ / 左ななめ後ろ / 左 / 左ななめ前

## 6. 実装上の制約（この環境）

| 機能 | Expo Go で可 | 備考 |
|---|---|---|
| 地図タップで選ぶ | ✅ | `MapView` の `onPress`（確定済み） |
| 場所検索（ジオコーディング） | ✅（要ネット） | `expo-location` の `geocodeAsync`（要確認） |
| 現在地・最近・お気に入り | ✅ | ローカルのみ |
| クリップボード取り込み | ✅ | `expo-clipboard`（要追加） |
| ディープリンク（exp://） | ✅ | `expo-linking`（要追加）。カスタムスキームは dev build |
| **ネイティブ共有ターゲット（ACTION_SEND）** | ❌ | Expo Go 不可。**development build 必須**（`expo-share-intent` 等）。APK ビルドが環境制約で不可のため、今回は「クリップボード取り込み」で代替し、共有ターゲットは実装計画のみ |

> ネイティブ共有ターゲットを実装するには development build（EAS Build）が必要。
> 本サンドボックスでは APK ビルドが不可のため（[production-build.md](docs/research/production-build.md)）、
> まず Expo Go で検証可能な経路（地図・検索・現在地・最近・お気に入り・クリップボード・ディープリンク）を完成させる。

## 7. データモデルの変更

```ts
interface Destination {
  // 既存
  id, name, point, createdAtEpochMs, origin
  // 追加
  favorite: boolean;        // ☆
  lastUsedAtEpochMs: number | null; // 最近使った順
}
```
- 既存データ（favorite/lastUsedAt なし）は読み込み時に `favorite: false, lastUsedAt: null` を補完（スキーマバージョンで移行）
- 最近使った場所 = `lastUsedAt` 降順の上位 5 件。お気に入り = `favorite === true`
- 目的地を選んだ時点で `lastUsedAt` を更新

## 8. 受け入れ基準（UX）

1. 一般画面に緯度・経度の入力欄が**存在しない**
2. 目的地設定は「地図から選ぶ」「検索」「現在地」「最近」「お気に入り」から**3 タップ以内**で完了する
3. メイン画面に Mock ボタン・記録タブ・生の精度数値が**常時表示されない**（要約 1 行のみ）
4. 権限拒否・位置不明・オフライン時に、次にすべきことが 1 文で分かる
5. 開発機能は長押し等の**隠し導線**からのみ到達できる
6. 主要ボタンのタップ領域 ≥ 48dp、主要数値の文字サイズ ≥ 40pt
7. 実機で F2〜F6 のフローが動作する（スクリーンショットで証跡）

## 地図（S4）の実装メモ（2026-10-30 更新）

- 地図は **OpenStreetMap**（無料・API キー不要）。Google Maps は使用しない。
- 表示: 現在地または選択地点を中心にタイル表示。右上に「＋」「−」（ズーム 10〜18）。
- 操作: 地図をタップ → マーカー表示 → 逆ジオコーディングで場所名 → 「この場所を目的地にする」。
- 帰属表示「© OpenStreetMap contributors」を常時表示（OSM の利用条件）。
- オフライン等でタイルが取得できない場合は「地図を読み込めません（通信状況を確認してください）」を表示（タップ選択自体は可能）。
- 共有（Google マップ等）: 共有シートに「寄鳥美鳥地」が表示され、短縮リンクは自動解決して確認シートを表示（場所名も取得）。

## 地図（S4）の操作改善（2026-10-30 追加）

- **地図をドラッグしてスクロール**できる（指に追従）。離した位置の中央が選択地点になる。
- **中央に固定ピン**を表示（ピンの先端が目的地候補）。ドラッグ中もピンは中央に固定。
- **ズーム**: ピンチ（2本指）・ダブルタップ・右上「＋」「−」。
- 文言: 「地図を動かして、ピンを目的地に合わせます」→ 確定は「この場所を目的地にする」。
- 帰属表示・タイル失敗時の案内は従来どおり。
