## D1 起動疎通・永続化

### 手順
1. Metro 起動 → `adb reverse` → `adb shell am start -a android.intent.action.VIEW -d "exp://127.0.0.1:8081"`
2. 初回起動を確認（プリセット目的地の投入・自動選択）
3. 目的地タブで別の目的地を選択 → アプリを force-stop → 再起動

### 結果
- **起動成功**: Metro ログ `Android Bundled 3289ms index.ts (881 modules)`。メイン画面が表示された
- **プリセット投入**: 目的地一覧に **東京駅 / 新宿駅 / 東京タワー** の 3 件が表示され、東京駅が「選択中」で自動選択された（`device-d1-destinations`）
- **実センサー動作**: 実 GPS で **12.81 km / 145°**、方位は **真北基準**で取得され、鳥が 145°（右下）を向いた（`device-d1-main-real`）
- **永続化**: 目的地を「東京タワー」に変更 → force-stop → 再起動 → **目的地「東京タワー」が復元**され、距離 9.61 km / 142° を再計算（`device-d1-persistence`）
- サンプル記録も復元・累積（D4 参照）

### 備考
- 初回起動時に **位置情報権限ダイアログ** と **位置精度（Google Location Accuracy）のシステムダイアログ** が表示された。後者は `getCurrentPositionAsync` の `mayShowUserSettingsDialog`（Android 既定 true）によるもの。許可すると高精度測位が有効になる
- 端末の位置情報サービスが OFF の場合は、開発画面の「直近エラー」に `services-disabled: 位置情報サービスが OFF です` が表示されることを確認（エラーハンドリング ✅）

## D2 鳥（オオハシ）の向き・回転

### 方法
実センサーに加え、Mock シナリオ「回転（方位1周）」で相対方位を変化させ、**相対方位の数値とオオハシのクチバシの向きを画面で照合**した。

| 相対方位（画面表示） | 期待される向き | 実機の表示 | 判定 |
|---|---|---|---|
| **145°**（実 GPS/コンパス） | 右下（南東寄り） | クチバシが右下 | ✅ |
| **218°**（Mock 回転） | 左下（南西寄り） | クチバシが左下 | ✅ |
| **188°**（Mock 回転） | ほぼ真下 | クチバシが真下 | ✅ |
| **到着（距離 0 m）** | 上向き固定 | クチバシが上・「到着」を大きく表示・相対方位「—」 | ✅ |

- **回転方向の符号は正しい**（+90° = 右 / 時計回り）。`Animated.View` の `transform: rotate` で滑らかに回転した
- 359°→1° の逆回転は目視で発生せず。**±720° 境界の逆回転修正**（`0df43cd`）はコードレビュー＋単体ロジックで担保（実機で 720° を跨ぐ操作は再現が困難なため、境界そのものの目視は未実施）
- 方位不明時（権限拒否・Mock「方位不明」）は**上向きニュートラル**＋「方位が分かりません」
- **±5° の目視精度**: 数値とクチバシの向きが一致することを複数角度で確認（厳密な角度測定は行っていない）

## D3 権限フロー

### 手順と結果
1. `adb shell pm revoke` で位置情報権限を剥奪 → 起動
   - アプリは**自動要求しない**（`undetermined & canAskAgain` のときだけ自動要求する設計）。メイン画面に **「位置情報が許可されていません」** の赤い案内＋**「再要求」「Mock で試す」** ボタンを表示（`device-d3-permission-denied`）
   - 状態は「測位中 / 位置 未取得 / 方位 未取得」、鳥はニュートラル。**クラッシュなし**
2. 「再要求」タップ → **Android の権限ダイアログ**が表示（「アプリの使用時のみ / 今回のみ / 許可しない」）（`device-d3-permission-dialog`）
3. 「アプリの使用時のみ」を選択 → **自動的に測位・方位取得が再開**し、12.81 km / 143° のナビゲーション表示に復帰（`device-d3-granted-recovered`）
4. 復帰後、GPS 精度 40 m のとき **「GPS 精度が不良です」**、方位が 11 秒古いとき **「方位情報が古くなっています」** の警告が表示された（FR-08 の警告系 ✅）

## D4 実センサー実測（記録・精度・鮮度）

### 結果（開発用画面）
- **サンプル記録**: リングバッファ上限 **300 件**まで蓄積。直近 20 件の表（時刻 HH:MM:SS / 緯度 / 経度 / GPS 精度）を表示（`device-d4-sample-log`）

### B. Mock 手動適用の不具合を発見・修正（コミット `2769f27`）

- **発見**: Mock ON → 手動入力（緯度 35.68959 / 経度 139.70041 / 方位 104 / 方位精度 3 / 真北）→ 適用 で、
  **位置は反映される（距離が 5.33 km に変化）が、方位が反映されない**（「方位 — (不明) / 基準不明」「方位が不安定です」）。
- **原因**: `MockHeadingProvider` が全 snapshot 変化で emit するため、`setManualLocation` の commit 直後に **null 方位を emit**。
  直後の有効値（104°）が `useNavApp` の **100ms 間引き**で捨てられ、null のまま固まる。
  加えて両 Mock プロバイダは**購読開始時に現在値を emit しなかった**（「適用 → Mock ON」の順で反映されない既知の注意点）。
- **修正**: 購読直後の初期 emit（force）+ **manual モードのみ dedupe**（scenario モードは毎 tick emit を維持）。
  回帰テスト 7 件を追加（位置だけ変更しても heading を再 emit しない、など）。**444 tests PASS**。
- **実機再確認の状況**: 位置反映は実機で確認済み。方位反映の再確認は、adb 自動操作（uiautomator 座標タップ + IME 無効化）の
  不安定さにより**完了できず**、回帰テストとコードレビューで担保した（手動操作での確認は次回）。
